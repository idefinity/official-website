# 把蠕动挪进顶点着色器，省下的 1.1 毫秒

环上的六边形一直在爬。爬的实现原本在 CPU：每帧把 644 个节点的 `s` 加上相位，
算一遍 `positionOnLoop`，再为 966 根连杆求中点、方向、从 +Y 到该方向的旋转，
写成 1610 个矩阵，上传。一帧 0.21 ms 花在公式上，剩下的花在矩阵和上传上。

## 做法

曲线是不动的，动的只有相位。所以把曲线烘成一张贴图：

- 2048 个采样点，每个点存中心点、法线、副法线，三行 RGBA16F
- 节点只需要 `(s, θ, r)` 三个数当实例属性，全部固定不变
- 相位变成一个 uniform `uCrawl`，每帧加一次

顶点着色器里三行把位置算出来：

```glsl
float u = fract(node.x + uCrawl) + 0.000244140625;
vec3 centre = texture2D(uFrames, vec2(u, 0.125)).xyz;
vec3 normal = texture2D(uFrames, vec2(u, 0.375)).xyz;
vec3 binormal = texture2D(uFrames, vec2(u, 0.625)).xyz;
```

加的那个小常数是半个纹素。纹理用 `RepeatWrapping`，`fract` 之后正好落在
采样点的左边界上，双线性过滤会把两个端点各取一半，接缝那一条线上就会糊一毫米。
偏移半个纹素，采样落在两个样本正中间，权重各半，接缝就看不出来了。

连杆麻烦一点：它必须同时看两端。两个端点各查一次贴图，在着色器里算差值、
长度、旋转矩阵，然后把圆柱沿这个方向拉长。`rotationBetween` 用罗德里格斯公式，
`c < -0.9999` 那个分支是为了反向平行时不除零。

节点的实例矩阵现在只装旋转和缩放，位置从着色器来。`project_vertex` 那段被整段
换掉了：先把 `instanceMatrix` 乘上去，再把曲线的偏移加上，最后才做视图投影。

## 数字

| | 挪之前 | 挪之后 |
|---|---|---|
| 主线程 / 帧 | 2.50 ms | **1.39 ms** |
| 其中脚本 | — | 0.93 ms |
| 帧率 | 30.0 | 30.0 |
| JS 堆 | 8–10 MB | 7.3 MB |

省下 1.1 ms。这一帧的预算是 33.3 ms，所以用户在 30 帧的锁下面感觉不到任何差别。
要说这一刀值不值：值，但理由不是这 1.1 ms。

真正的收益是结构上的。以前"环上有多少节点"和"每帧要做多少活"是同一件事，
加密度就变慢。现在每帧的活是一个 uniform 加三次 draw，跟节点数量无关。
以后想把 644 个节点加到 2000 个，主线程那条线基本不动。

## 踩到的两个坑

**three 的程序缓存按着色器文本做 key。** 节点和连杆共用 `loopPosition` 这段
GLSL，但整体代码不同。改完之后连杆悄悄用上了节点的程序——因为 three 在
`customProgramCacheKey` 缺省时只看材质类型和几项开关，不看我们注入的文本。
表现为连杆完全消失。加一行 key 就好了：

```ts
material.customProgramCacheKey = () => (uniforms ? `loop-${part}` : "loop-plain");
```

这个坑只有一半时间会踩到（取决于两个材质的编译顺序），所以复现起来很烦。
写在这里是为了下次直接想起来。

**半浮点的精度。** 贴图用 `HalfFloatType`：在手机上没有浮点纹理线性过滤的保证，
半浮点是 WebGL2 核心。这个尺度下的误差约 0.001 个世界单位，屏幕上四分之一个像素，
看不见。换 `FloatType` 能省掉这点误差，代价是手机上可能直接不可用。

## 顺带

蠕动原来有个"加速冲量"：翻页时 `nudge()` 让相位突然快一下再收回来。
挪到 GPU 之后这段逻辑一行没改——它还留在 CPU 那边管相位，GPU 只是被动地读。
这说明切的位置是对的：变化快的量留在 CPU，几何和曲线留在 GPU。
